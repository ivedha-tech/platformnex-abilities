# Contributing

1. Every change starts from an issue.
2. Branch from `main`: `feat/<issue>-slug`, `fix/<issue>-slug`, `chore/...`, `hotfix/...`.
3. Run `make check` before pushing. It is the same thing the pipeline runs.
4. Commits are signed and follow Conventional Commits. PRs are squash-merged.
5. Keep PRs small (aim for under 400 changed lines) and fill in the template.
6. One approval from a code owner who is not you. Resolve every thread.
7. AI-assisted changes are welcome and are held to the same bar: you read
   every line and you are the author.

The full lifecycle and its gates are in the engineering handbook.
